本書は、初学者向け教材を企画・執筆し、教育内容と実装をレビューするための作業基準です。説明順序、節数、演習数、図の数や形式を一律にそろえる規則ではありません。教材データ、画面、route、保存形式の契約を独自に変更する許可でもありません。

## 1. 教材を設計する

### 1.1 学習目標を観察できる行動で書く

「理解する」「知る」だけで終えず、学習後に何を説明・計算・分類・比較・選択できるかを書きます。適用条件を判断する教材では、その条件や理由を説明できることも目標に含めます。

各目標について、本文で扱う場所、学習者が練習・評価される行動、その達成を判断する根拠を対応付けます。表または相互参照で、少なくとも次の項目を追えるようにしてください。

| 学習目標（到達行動） | 本文・具体例 | 演習・評価で求める行動 | 達成を判断する根拠 |
| --- | --- | --- | --- |
| 新しい事例で対象を分類し、その理由を説明する | 分類基準と対照的な既知の例 | 別の事例について対象・分類・理由を答える | 観測対象と分類基準の両方が合っている |

1目標につき1問を作る必要はありません。一つの課題で複数の目標を評価しても構いません。大事なのは、各目標をどこで扱い、どの証拠で達成を判断するかが読めることです。

### 1.2 標準的な説明順序を出発点にする

標準形は次の順序です。教材の学習目標や性質に合わせて一部を省略したり、前後させたり、まとめたりできます。

| 順序 | 学習上の役割 | 確認すること |
| --- | --- | --- |
| 疑問・目的 | 学ぶ理由を具体的にする | どの問いに答える教材かが分かる |
| 現実的な事例 | 抽象概念の対象を置く | 誰・何を、どの単位で観察するかが分かる |
| 観察と直感 | 結果や違いを先に眺める | 結論を急がず、次の説明につながる問いがある |
| 用語・式・適用条件 | 正確な定義と使える範囲を示す | 記号、単位、前提、適用条件、限界が説明される |
| 解法・判断の実演 | 考え方を一例で見せる | 手順だけでなく、その判断を選ぶ理由が追える |
| 小演習 | 直前の目標を確かめる | 学習者自身が考える余地を残している |
| 応用・次単元 | 別の状況や次の学習につなぐ | 適用範囲と次に進む理由が分かる |

計算中心でない単元では、分類の比較や判断理由の検討を中心にします。「解法の実演」は分類根拠を説明する例に置き換えられます。本文・表・静止図・操作できる図・演習のどれを使うかも目標から選びます。

順序・要素・媒体を変えるときは、次の観点で判断し、レビューに理由を残します。

- 学習目標に必要な情報と判断機会が残り、省略した説明や評価が別の場所にあるか。
- 選んだ媒体が必要な情報を過不足なく伝え、学習者が結果を読み取れるか。
- 用語を理解に必要となる前に導入し、読解、操作、復習先との往復にかかる負担が目標に見合うか。
- 各目標を扱う本文・例・評価の場所と、その配置を選んだ理由が対応しているか。

節数・問題数・図の数を数合わせするためだけの追加はしません。反対に、形式を簡素にする場合も、必要な目標や判断の練習が抜けていないかを確認します。

### 1.3 初学者向けの文章を、正確さを保って書く

- 平易で短い文と具体例から入り、必要な専門用語・定義・記号・条件は省略せず説明します。比喩や直感的な説明は定義の代わりにしません。
- 既習前提を尊重し、前提の説明を毎回繰り返しません。未習の記号・計算・概念が必要なときは、本文を過密にせず対応する節や前提への導線を示します。
- 数式を出すときは、式が何を求め、各記号と単位が何を表し、どの条件で使えるかを読み解きます。計算結果の意味と解釈上の限界も示します。
- 母集団の量、標本から計算した値、推定量の性質を混同しません。「平均で一致する」などの主張は、対象・条件・確率的な意味を明記します。
- 誤解しやすい用語は、適切な対照例を使って区別します。条件を弱めたり例外を隠したりして、文章を短くしないでください。

**計算型の文章例（新規の例示）**

- 避ける例：「n−1で割れば、標本ごとに母分散に近い値が得られます。」
- 望ましい例：「同じ母集団から互いに独立に取った n 個（n≥2）のデータで母分散を推定するには、標本平均からの偏差平方和を n−1 で割ります。母分散が有限なら、同じ条件で標本を取り直すときに得られる推定値の期待値は母分散に一致します。1回ごとの推定値には、標本によるばらつきがあります。」
- 理由：n−1で割る対象を特定し、推定値の期待値と一つの標本から得られる値を区別します。

## 2. 演習と誤答後の復習を設計する

### 2.1 目標に合う判断を評価する

演習では、学習目標に応じて次の観点を組み合わせます。すべての問題に全観点を詰め込む必要はありません。

- **手順：** 計算や式の展開を正しく進められるか。
- **意味：** 数値・記号・単位・分類が何を表すか説明または識別できるか。
- **適用判断：** どの方法・尺度・分類を使うか、その条件や根拠を判断できるか。
- **誤解の発見：** 例に含まれる誤った対象の数え方、式の適用、説明などを指摘できるか。

問題は学習目標に対応させ、解説に必要な途中式・判断根拠・単位を含めます。誤答理由をシステムが区別できる根拠がある場合にのみ、その理由を特定して説明します。根拠がない数値誤答では誤解を決めつけず、正しい考え方や確認箇所を示します。

自分の言葉で説明できるかを見る場合は、解答例との照合や学習者自身の確認など、実際に用意できる方法を明記します。自由記述を自動採点できるかのように案内しません。

### 2.2 正答を隠し、採点後の説明を役立てる

現行の共通演習表示との整合を保つため、次をチェックします。

- 解説は初期状態で閉じ、設問の初期表示に正答や正しい途中式を混ぜません。
- 学習者は採点前でも必要なら解説を手動で開けます。正答時は現行UIが解説を自動で開き、誤答・形式不正時は自動では開きません。
- 誤りを発見する問題では、判断材料となる誤った式や手順を設問に見せられます。正しい解法・修正は閉じた解説側に置きます。
- 正誤と入力形式の不正を区別します。複数欄なら、どの条件で全体が正解になるかを曖昧にしません。
- 誤答後に関係する節・前提へ移動でき、元の問題へ戻って再回答できるかを確認します。復習先は実在する参照先にします。

### 2.3 固定問題・生成問題の整合を確かめる

固定問題では、問題文、答え、採点条件、単位、解説、復習先が一致することを確認します。生成問題では、同じ実装と同じ生成条件（現在は `index` または `seed` を使う箇所があります）から問題、選択肢、正答、説明、参照先が一体として再現されることを確かめます。

値を変更する場合は、変更対象だけが更新され、回答・フィードバック・解説表示が適切に初期化されること、別設問や保存対象を誤って変えないことを確認します。適用条件、単位、丸め、入力形式、境界値、選択肢の一意性も含めて採点を照合します。固定問題に生成用seedを必須化するなど、教材に不要なフィールドや仕組みは追加しません。

## 3. 図・表・本文を使い分ける

本文や表だけの場合と比較して、関係の把握・理解・判断を助ける教育上の役割が明確な図を採用します。図は説明を置き換える場合だけでなく、説明した平均と偏差の関係を数直線で示すように、理解を補強する場合にも使えます。装飾だけを目的とする図や操作は追加しません。学習者が値を変えたときの傾向や関係を予測・比較する目標では操作できる図を、分類の違いを並べて判断する目標では比較表で十分かを検討します。

図・グラフを採用するときは、次を確認します。

- その図で何を理解・比較・予測するのかという教育上の目的。
- 変数と意味、軸・尺度、単位、凡例、読み取るべき関係。
- 操作がある場合の入力方法と、操作後に対象や結果が画面内で見えること。
- 教材データにある説明（例：`educationalPurpose`、`variables`、`axes`、`legend`、`altText`）と、画面で実際に描画される `rendererRef` の一致。
- 図がコードから再現可能なこと。生成画像・生成アセットは使いません。

操作はキーボードで行え、可視フォーカスがあり、操作対象が画面上で見え、マウス・タッチでも使えるようにします。既存の `altText` やARIA属性は保ちます。現行の[AGENTS.md](../../AGENTS.md)に従い、スクリーンリーダー固有の追加開発・検証は受入条件にしません。

## 4. 出典・クレジットを追跡する

教材本文・設問・図は独自制作を基本にし、出典を示すことと原文を複製することを区別します。参照した資料は、利用者またはレビュアーが再確認できるよう次の情報を記録します。

| 項目 | 記録内容 |
| --- | --- |
| 資料 | 正式な資料名、著者・発行元 |
| 到達先 | 直接確認できるURL |
| 版 | 版、規格番号、公開日など資料を特定する情報 |
| 確認日 | 内容を確認した日 |
| 該当箇所 | 章、節、表、ページなど |
| 用途 | 定義・条件・学習順序など、何の根拠に使ったか |
| 利用条件 | 引用の範囲、著作権、コードや素材のライセンス、必要なクレジット |

登録された出典欄があるだけで完了とはせず、教材画面から参照先にたどれるか確認します。公式出題範囲の参照、一般単元の本文に置く参考資料、基本統計量の専用画面にある `references`・`credit` は現行の表現例であり、全単元に同じデータ構造を強制する決定ではありません。既存の `sourceItemIds` と導出される `sourceRefs` の契約を変える場合は、Issueで判断し、関連validator・テストとの整合を確認します。

外部コードや素材を使うときはライセンスを確認します。新たな依存が必要なら、既存機能で足りない理由、配信物に含まれる範囲、ライセンスをPRに記録します。

## 5. 教材・学習記録の実装契約を守る

教育上の提案と現在の実装契約を混同しないでください。設計判断の正本は関連Issueと明示された後続決定であり、現行挙動は実装・validator・テストを照合します。契約変更が必要なら影響と移行方針を先に記録し、該当Issueの範囲で判断します。

| 区分 | 制作・レビューでの扱い |
| --- | --- |
| 教育上の原則 | 目標と説明・評価の対応、説明の正確さ、誤答説明の根拠を確認する。適用先の性質に応じて実現方法を選ぶ。 |
| 実装上の必須契約 | 現行の正本、型、validator、テストを確認する。ID・参照・route・復習導線・保存値・エラー処理への影響を調べる。 |
| 現行仕様の例 | 確認した時点の実例として扱い、将来の全単元に固定しない。 |
| 未決事項 | 後続Issueで必要性と根拠を確かめ、提案・採否を記録する。決定前に要件扱いしない。 |

具体的には次を照合します。

- 教材データの正本は [`src/lesson-registry.mjs`](../../src/lesson-registry.mjs)。`lessonId`、`sectionId`、演習ID、図ID、教材参照は既存の外部リンクとして扱い、無断で変更しません。
- 教材と演習の型・実行時検証は [`src/lesson-contract.d.mts`](../../src/lesson-contract.d.mts)、[`src/lesson-contract.mjs`](../../src/lesson-contract.mjs) と関連する契約テストで確認します。
- 本文中のlessonRef、節内の `exerciseSlot`、演習定義・採点・復習先は相互に実在性と整合を確認します。一般単元で使える `exerciseSlot` と、独立演習画面・保存履歴の現行対象範囲は別の話です。基本統計量の5カテゴリは現行例であって、全単元に同じ独立演習画面や履歴を義務づけません。範囲を広げるときはIssueで必要性と影響を記録します。

### 独立演習の初回有効判定（現行例）

現行の独立演習では、各問題インスタンスの最初の有効な採点だけをページ集計に反映し、保存できた場合はその判定を履歴に記録します。未回答や形式不正は有効な採点ではなく、履歴・集計に入りません。以下の履歴列は保存が正常に完了した場合の結果です。保存失敗時は既存のエラー処理に従います。これは既存の基本統計量演習の挙動例であり、全単元に独立演習や履歴を追加する要件ではありません。

| 操作 | 問題カードとページ集計 | 履歴 |
| --- | --- | --- |
| 最初に誤答し、同じ問題で正答し直す | 最初の誤答後はカードに誤答を表示し、ページ集計は「正解 0 / 5 問（答え合わせ済み 1 問）」。正答し直すとカードのフィードバックは正答に変わり、解説が開くが、ページ集計は初回判定のまま。 | 初回の誤答1件を記録する。正答し直しても、その記録を正答に置き換えず、同じ問題から履歴を追加しない。 |
| 形式不正の後、同じ問題で初めて有効な正答をする | 形式不正のメッセージを表示し、ページ集計はその問題を未回答のままにする。有効な正答後はカードに正答を表示して解説を開き、集計は「正解 1 / 5 問（答え合わせ済み 1 問）」。 | 形式不正は記録しない。有効な正答を1件記録する。 |
| 別問題への変更に成功する | 変更したカードの回答・フィードバック・解説開閉状態を初期化し、ページ集計ではその枠を未回答に戻す。他の問題の状態は保つ。 | 前の記録を置き換えず、新しい問題インスタンスの最初の有効判定を別の記録として追加する。保存履歴は既存の直近25件上限に従う。 |

問題の再生成に失敗した場合は、現在の問題とその回答・フィードバック・集計状態を保ち、生成エラーを表示します。保存失敗時の扱いは上の保存・エラー処理契約に従います。
- 本文中の `lessonId#sectionId` は教材内参照の表記であり、hash URLそのものとは限りません。実際のhash routeへの解決、復習stack、節参照を通る往復を維持します。手動の学習完了と自動採点・演習正答率は独立させます。
- 学習状態、演習履歴、バックアップの形式・入力検証・保存失敗・破損データのエラー処理は、[`src/learning-state.mjs`](../../src/learning-state.mjs)、[`src/practice-results.mjs`](../../src/practice-results.mjs)、[`src/backup.mjs`](../../src/backup.mjs) と関連テストに照らして保護します。正式リリース前の旧形式との後方互換性は、個別指示がない限り要件ではありません。現行データの整合性検証とエラー処理は引き続き必要です（[AGENTS.md](../../AGENTS.md)）。

## 6. レビュー用チェックリスト

### 解説・教材構成

- [ ] 到達目標が学習後に観察できる行動で書かれている。
- [ ] 目標ごとに本文・例、演習・評価、達成を判断する根拠をたどれる。
- [ ] 標準順序から変えた場合、必要な情報・判断機会がどこで補われるか説明できる。
- [ ] 事例の観測対象・単位・条件が分かり、導入の問いが目標につながる。
- [ ] 既習前提を尊重しつつ、未習の前提や記号への導線がある。
- [ ] 用語、式、単位、条件、仮定、適用範囲が正確で、比喩が定義を歪めていない。
- [ ] 節・問題・図を、数をそろえる目的だけで増減していない。

### 演習・採点・誤答後の復習

- [ ] 演習で問う手順・意味・適用判断が目標と合っている。
- [ ] 初期の設問表示に正答・正しい途中式が漏れず、解説は初期閉鎖である。
- [ ] 固定値または生成条件から問題・採点・解説・参照先を照合できる。
- [ ] 入力形式、丸め、単位、境界値、複数欄、選択肢の一意性を確認した。
- [ ] 根拠のない誤答理由を断定せず、必要な途中式・考え方を示している。
- [ ] 関連する解説・前提に移動し、元の問題に戻って再回答できる。

### 図・出典・実装

- [ ] 本文や表だけの場合と比較して、関係の把握・理解・判断を助ける図の教育上の役割が明確である。
- [ ] 図の変数、軸・尺度、単位、凡例、操作方法が分かり、rendererが登録内容に合う。
- [ ] 操作のキーボード利用、可視フォーカス、画面内の対象可視性、マウス・タッチを確認した（操作がある場合）。
- [ ] 出典の版・確認日・該当箇所・用途を記録し、権利・ライセンスと表示を確認した。
- [ ] 安定ID、節参照、route、手動進捗・演習履歴・保存・バックアップ契約を照合した。

## 7. 基本統計量の良い例と構成を変える例

### 7.1 基本統計量：共通の事例で4つの量を結び付ける

基本統計量では、目標長さ100 mmのシャフトを作る2ラインを各3本測り、次の問いを置きます。

| ライン | 測定値（mm） | 平均 |
| --- | --- | ---: |
| A | 98, 100, 102 | 100 mm |
| B | 99, 100, 101 | 100 mm |

平均が同じでも散らばりは異なるという疑問を入口にし、平均・偏差・分散・標準偏差を連続して説明するのは、4つの量の関係が一つの文脈で分かるためです。基本統計量の節数・図数・問題数を他単元に強制しません。

### 7.2 データの種類：観測単位を決めてから分類する

Issue [#113](https://github.com/painkiller8880888/SfQC/issues/113) での適用例です。次の構成は、非計算型の教材がv0を使えるか検討するための例であり、節数・問題形式・図の採否を先取りして固定しません。

| 内容 | 例 | 目標と評価の対応 |
| --- | --- | --- |
| 導入する判断 | 「何を1件として記録するか」を先に決める。製品ごとの寸法・傷の件数・適合状態なら観測単位は製品。傷の種類なら傷1件が単位。 | 観測単位を決めてから分類する。 |
| 測定値 | 3製品の長さをmm単位の整数に丸めて12 mm、12 mm、13 mmと記録する。記録の精度と、測定対象である長さの性質を区別する。 | 整数で記録したことだけでは長さが離散量にならない理由を説明する。 |
| 件数とカテゴリ | 製品ごとの傷の件数2、0、1は離散的な数。適合／不適合を0／1で記録しても、0／1がラベルならカテゴリである。 | 数値表記と、値が表す対象・量を区別する。 |
| 集計対象 | 製品10個を調べ、製品Aに不適合な傷が2件、Bに1件、残り8個に0件なら、不適合品数は2個、不適合数は3件。 | 何を数えたかを説明し、品物単位と不適合単位の値を区別する。 |
| 演習・判断 | 説明に使った例とは異なる事例で、記録の観測単位、データの種類、そう判断した理由を答える。 | 分類名だけでなく、対象と判断根拠が合っていることを評価する。 |

比較表で必要な違いを伝えられるなら、装飾的な図や計算問題は加えません。固定選択式の節内確認を使う場合も、分類ラベルだけでなく観測単位と判断理由の組を選ばせるなど、目標の適用判断を評価します。自分の言葉による説明は記述例との照合や学習者の自己確認で扱い、自由記述の自動採点を前提にしません。

**分類型の文章例（新規の例示）**

- 避ける例：「傷が3件なので、不適合品は3個です。」
- 望ましい例：「製品10個を検査したところ、検査基準に適合しない傷が、製品Aに2件、製品Bに1件ありました。残りの8個に検査基準に適合しない傷はありませんでした。傷を1件ずつ数えると不適合数は3件です。該当する傷がある製品を1個ずつ数えると不適合品数は2個です。」
- 理由：製品単位と傷単位、および集計対象を示し、二つの値を判断できるようにします。
