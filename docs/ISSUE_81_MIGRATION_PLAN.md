# 基本統計量の本実装への移行計画

2026-11-12時点の計画です。#81の比較用モックを仮採用した後の実装順と、その完了条件を記録します。比較結果・判断理由・追加受入検証は再掲せず、完了済みの比較作業を再要求しません。本書は実装の承認済み範囲を示しますが、全教材への展開や正式公開を承認するものではありません。

元になった2026-11-12の「学習導線・進捗管理 再設計ドラフト」と、Issue #43・#73・#81、既存の契約記録、およびそれらに対するユーザーの後続決定を反映しています。本書の後続決定と衝突する#81の旧受入条件は、その範囲で本書を優先して置き換え、それ以外の受入条件と変更していない契約は維持します。

## 移行後の契約

### 学習画面と教材

- 主要な導線はマップ・教材・進捗の3領域とし、教材には「基本統計量」の4節を連続表示する解説ページと、別ページのコース演習を置きます。既存の画面枠とテーマを使い、解説と演習を一画面に統合した表示とは扱いません。
- コースID `descriptive-statistics` と節ID `mean`・`deviation`・`variance`・`standard-deviation` を保ちます。節リンクは `#/course/<courseId>/lesson/<sectionId>`、演習は `#/course/<courseId>/practice` とし、節リンクは描画後に該当位置へスクロールしてフォーカスします。マップから解説・演習へ直接進め、誤答から関連解説・前提節へ移動して再演習できるようにします。答え合わせ後の説明・再生成は演習ページ内で行い、別のfeedback画面や復帰stackを設けません。
- マップのノードは完了マークと直近正答率を示し、詳細から解説・演習へ直接進めます。マップの前提矢印は共通必須前提に限り、条件付き前提や任意復習は解説・演習のリンクから辿れるようにします。
- 解説は身近な事例と直感から始め、観察、考え方、必要な用語・式、小さな練習へ進みます。平易な説明でも数理的な正確さを保ちます。解説内の小問が必要な箇所は専用の演習slotで表し、通常の本文と独立した演習ページの境界を崩しません。
- 教材本文の正本は `src/lesson-registry.mjs` に置き、画面との二重管理をなくします。既存の4 blockとoverview契約に必要な最小拡張を加えます。汎用 `widgetRef` は導入せず、操作図4種と `VarianceSimulation` は既存の `figureRef` の `code:` 登録を拡張して利用します。
- 図はコード描画とし、操作・数値・説明を同期させ、キーボード操作と同等のテキスト情報を用意します。生成画像・生成アセットは使いません。
- モックで採用した5カテゴリ各3テンプレートをコース演習定義へ移します。問題文に答えを漏らさず、答え・考え方の解説は初期状態で閉じます。問題ごとの再生成では、その問題文・解答・計算過程・関連図だけを同じ入力から更新し、解説を閉じます。
- 出典情報は保持します。通常の参考資料は折りたたみ、ライセンス上常時必要なクレジットはページ下部に読める形で示します。外部リンクはHTTPSのみとし、ドメイン許可リストは設けません。

### 採点、記録、進捗

- 数値採点は `Number` と epsilon `1e-6` の比較から、許容誤差0の十進採点へ切り替えます。回答桁数を問題文に明示し、整数回答では整数指定を明示します。回答が指定桁数を超えても受け付け、入力と期待値をその桁数へ丸めてから一致判定します。十進文字列を使い、ちょうど半分は絶対値の大きい側へ丸めます。既存 `src/question-grading.mjs` のBigInt十進丸めから比較に必要な部分だけを再利用し、snapshot依存の公開APIはそのまま新形式へ持ち込みません。数値形式として不正な入力は引き続き拒否します。初回問題は整数解で構成し、汎用の分数・平方根基盤を先行させません。
- 保存領域は2つに分けます。手動完了日時（未完了はnull）とマップ配置を一方に、演習判定をもう一方に保存します。手動進捗は完了/未完了の2値で、設問ごとの完了チェックは保存しません。完了状態は演習成績で変わりません。新形式へ切替後の統合バックアップは両方を含み、書き出し・復元・破損時の案内へ進捗画面などから到達できるようにします。
- 初回実装で判定記録に含めるのは、別ページのコース演習にある既存5カテゴリ（「平均と偏差」「データの変換」「不偏分散」「総合」「分散と標準偏差」）の判定だけです。解説節内の小問は回答・採点・feedbackを維持しますが、判定履歴、直近25件の対象、正答率の分母には含めません。保存するカテゴリIDの許可集合はこの5カテゴリに限定し、第1段階でschemaを確定する前に決めます。将来の対象拡張を見越したschema機能は作りません。
- 演習判定はコース全体で直近25件を保持し、カテゴリごとに25件とはしません。1件の記録は上記5カテゴリのいずれかのカテゴリID・正誤・日時だけとし、設問文・回答・snapshotは保存しません。直近正答率は分子と分母（保存対象となった演習判定数）を示し、判定0件は「未記録」、演習定義のないコースは「演習なし」と区別します。
- 同じ表示中の問題では最初の答え合わせだけを記録します。再回答で履歴を追記・変更しません。問題を再生成すると初回判定状態をリセットします。再訪・再読み込みは新しい出題として扱える最小案とし、永続snapshotは導入しません。保存に失敗した最初の結果は画面上に保持し、同じ結果の保存を再試行できるようにします。
- 手動完了と判定集計は独立させます。登録済みで演習のない5コースは「演習なし」と表示し、手動完了できます。未収録の28コースは目標と「未収録」を表示し、完了にできません。
- 進捗一覧は既定でマップ順にし、低正答率順へ切り替えられるようにします。完了操作は明示的な利用者操作に限り、解説閲覧や正答率で自動完了・アクセス制限を行いません。

### 保存・互換性

- 新しい保存キー、version、上限、上記5カテゴリに限定したカテゴリID許可集合と検証方法を第1段階で定義・実装します。保存値の入力検証、破損・不正データ、容量超過、書き込み失敗のエラー処理を保ちます。新形式のbackup書き出しと復元は両領域を一体として検証します。
- 第1段階では新形式と統合backupを未接続の基盤として実装します。本番の既存 `sfqc:local-data`・`sfqc:map-state:v1` の読み書きと既存backupの書き出し・復元は切り替えず、第2段階でUI、保存の読書き、backupの入口・書き出し・復元を同じ変更で新経路へ一斉に切り替えます。第2段階の切替が完了するまで新旧機能を部分的に混在させず、旧側だけを使うため、段階PRのmerge間に進捗表示やbackupが新旧で食い違う状態を作りません。
- 切替前は既存経路が旧キーと既存backupを使い、切替後の新経路は旧形式を読み込みません。旧データの変換、dual-write、互換アダプター、自動削除は行わず、正式リリース前の後方互換性を要件に含めません。これは2026-11-12の明示的な方針であり、#43等の以前の互換条件をこの範囲で改訂します。
- 2領域に分けただけで複数キーの更新が原子的になる、または複数タブ競合がなくなるとは扱いません。部分保存・競合時の状態、再試行、復元の挙動を第1段階で定義して検証します。

## 3段階の実施順

### 1. 未接続の基盤を準備する

新しい2領域の保存形式、検証と失敗時の回復、両領域を含むbackup、十進採点の入口を未接続の基盤として実装します。本番UIや現在の `sfqc:local-data`・`sfqc:map-state:v1` の読書き・既存backupには接続せず、旧形式のmigration、dual-write、互換アダプターは作りません。

**完了条件:** 保存形式のkey/version/上限と、既存5カテゴリだけを許すカテゴリID契約をschema確定前に定め、正常・不正・破損・容量超過・保存失敗を検証できること。2領域の片側だけが更新された場合や複数タブから更新された場合の表示・復旧方法が決まっていること。新形式のbackupを単独で往復し両領域を復元できる一方、本番の旧キー読書き・既存backupは未接続のまま維持されること。十進採点は、`roundingDigits=2` の正答 `1.23` に対する入力 `1.234` を正答とし、丸め後に不一致となる入力を誤答とすること。正負のちょうど半分は絶対値の大きい側へ丸め、整数桁指定（0桁）でも判定でき、数値形式が不正な入力は拒否し、指定桁を超える入力を桁数だけで拒否しないこと。許容誤差0であること。

### 2. 基本統計量を新経路へ一斉に切り替える

4節の連続解説ページと別ページの演習を `lesson-registry` 正本で実装し、必要な本文block・overview・演習slotと図の登録だけを追加します。新しい演習定義、初回判定、コース全体の直近25件を接続します。マップ・進捗UI、保存の読書き、backupの書き出し・復元を同じ変更で新経路へ切り替え、第1段階で未接続だった形式を初めて本番導線から使います。初回実装の直近25件には演習ページの既存5カテゴリだけを含め、解説節内の小問は回答・採点・feedbackを提供したまま、判定記録や正答率には含めません。

**初回切替の範囲:** 基本統計量の4節と1ページの演習、演習ページの既存5カテゴリだけを対象とするコース全体の直近25判定、独立した手動完了、統合backup往復。他の収録済み5コースは演習なし・手動完了可、未収録28コースは完了不可とします。

**完了条件:** マップ・進捗UI、保存の読書き、backupの入口・書き出し・復元が一つの新経路へ切り替わり、旧キーと旧backupの一部だけが画面や保存経路に残る混在がないこと。初回判定・再回答・問題再生成・再読み込み、既存5カテゴリのみの対象範囲、0件表示「未記録」と分母、25件上限、節リンクと誤答後の復習導線が期待どおり動き、採点・進捗・演習記録が互いを自動更新しないこと。`lesson-contract`、`lesson-view`、`resolve-screen`、backup/store、演習統合のテストを通し、正負の丸め、破損・保存失敗も確認すること。画面変更はproduction buildで320px幅・キーボード・ブラウザー経路を確認すること。

### 3. 旧機能を整理する

第2段階で新経路への一斉切替を完了し、その動作を確認した後、旧演習・feedback画面、preview分岐、旧保存・backup経路、不要になった履歴snapshotと関連経路を削除します。`question-*` を一括削除せず、採点と他の収録済み教材5コースからの参照を確認して対象を絞ります。必要な文書と受入記録を更新します。

**完了条件:** 基本統計量が新経路だけで利用でき、対象外の収録済み教材と共有採点部品に回帰がないこと。`npm run check` と `npm run build` が通り、公開QAが対象Issueで必要な場合はその結果も記録されていること。

各段階は依存順に進め、作業は原則としてIssueごとに分けてPRにします。段階間で新旧経路を同時に恒久運用することや、2つ目のコースを新形式で制作することは前提にしません。

## 実装時の検証と範囲外

- 実装中は `npm run check`、`npm run build` と変更した契約・画面・保存・演習統合テストを行います。今回の計画文書PRではコードテストやブラウザー検証を追加しません。
- 第1段階の採点テストでは、`roundingDigits=2` で期待値 `1.23` に入力 `1.234` は正答、丸め後に一致しない入力は誤答、正負のちょうど半分は絶対値大側へ丸めること、整数桁指定（0桁）、数値形式が不正な入力の拒否を確認します。指定桁を超えること自体は拒否理由にしません。第2段階ではこの採点契約に加え、0件・25件上限、初回だけの記録、再生成、保存失敗、破損データ、backup往復、コース分類、ルート遷移とキーボード操作を確認します。これは新実装の機能検証であり、完了済みのモック比較受入検証をやり直すものではありません。
- 対象外は、他教材への新形式展開、2つ目のコース制作、旧データの移行、サーバー・アカウント、生成画像、汎用widget機構、数値採点の汎用分数・平方根対応です。
