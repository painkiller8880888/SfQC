# 基本統計量の本実装への移行計画

2026-11-12時点の計画です。#81の比較用モックを仮採用した後の実装順と、その完了条件を記録します。比較結果・判断理由・追加受入検証は再掲せず、完了済みの比較作業を再要求しません。本書は実装の承認済み範囲を示しますが、全教材への展開や正式公開を承認するものではありません。

元になった2026-11-12の「学習導線・進捗管理 再設計ドラフト」と、Issue #43・#73・#81、既存の契約記録、およびそれらに対するユーザーの後続決定を反映しています。旧Issue本文との衝突は、本書に記録した後続決定の範囲だけを置き換え、それ以外の契約は維持します。

## 移行後の契約

### 学習画面と教材

- 主要な導線はマップ・教材・進捗の3領域とし、教材には「基本統計量」の4節を連続表示する解説ページと、別ページのコース演習を置きます。既存の画面枠とテーマを使い、解説と演習を一画面に統合した表示とは扱いません。
- コースID `descriptive-statistics` と節ID `mean`・`deviation`・`variance`・`standard-deviation` を保ちます。節リンクは `#/course/<courseId>/lesson/<sectionId>`、演習は `#/course/<courseId>/practice` とし、節リンクは描画後に該当位置へスクロールしてフォーカスします。マップから解説・演習へ直接進め、誤答から関連解説・前提節へ移動して再演習できるようにします。答え合わせ後の説明・再生成は演習ページ内で行い、別のfeedback画面や復帰stackを設けません。
- マップのノードは完了マークと直近正答率を示し、詳細から解説・演習へ直接進めます。マップの前提矢印は共通必須前提に限り、条件付き前提や任意復習は解説・演習のリンクから辿れるようにします。
- 解説は身近な事例と直感から始め、観察、考え方、必要な用語・式、小さな練習へ進みます。平易な説明でも数理的な正確さを保ちます。解説内の小問が必要な箇所は専用の演習slotで表し、通常の本文と独立した演習ページの境界を崩しません。
- 教材本文の正本は `src/lesson-registry.mjs` に置き、画面との二重管理をなくします。既存の4 blockとoverview契約に必要な最小拡張を加えます。汎用 `widgetRef` は導入せず、操作図4種と `VarianceSimulation` は既存の `figureRef` の `code:` 登録を拡張して利用します。
- 図はコード描画とし、操作・数値・説明を同期させ、キーボード操作と同等のテキスト情報を用意します。生成画像・生成アセットは使いません。
- モックで採用した5カテゴリ各3テンプレートをコース演習定義へ移します。問題文に答えを漏らさず、答え・考え方の解説は初期状態で閉じます。問題ごとの再生成では、その問題文・解答・計算過程・関連図だけを同じ入力から更新し、解説を閉じます。
- 出典情報は保持します。通常の参考資料は折りたたみ、ライセンス上常時必要なクレジットはページ下部に読める形で示します。外部リンクはHTTPSのみとし、ドメイン許可リストは設けません。

### 採点、記録、進捗

- 数値採点は `Number` と epsilon `1e-6` の比較から、許容誤差0の十進採点へ切り替えます。回答桁数を問題文に明示し、整数回答では整数指定を明示します。十進文字列を使い、ちょうど半分は絶対値の大きい側へ丸めます。既存 `src/question-grading.mjs` のBigInt十進丸めから比較に必要な部分だけを再利用し、snapshot依存の公開APIはそのまま新形式へ持ち込みません。問題定義と回答の検証は維持します。初回問題は整数解で構成し、汎用の分数・平方根基盤を先行させません。
- 保存領域は2つに分けます。手動完了日時（未完了はnull）とマップ配置を一方に、演習判定をもう一方に保存します。手動進捗は完了/未完了の2値で、設問ごとの完了チェックは保存しません。完了状態は演習成績で変わりません。統合バックアップは両方を含み、書き出し・復元・破損時の案内へ進捗画面などから到達できるようにします。
- 演習判定はコース全体で直近25件を保持し、カテゴリごとに25件とはしません。1件の記録はカテゴリID・正誤・日時だけとし、設問文・回答・snapshotは保存しません。直近正答率は分子と分母を示し、判定0件は「未記録」、演習定義のないコースは「演習なし」と区別します。
- 同じ表示中の問題では最初の答え合わせだけを記録します。再回答で履歴を追記・変更しません。問題を再生成すると初回判定状態をリセットします。再訪・再読み込みは新しい出題として扱える最小案とし、永続snapshotは導入しません。保存に失敗した最初の結果は画面上に保持し、同じ結果の保存を再試行できるようにします。
- 手動完了と判定集計は独立させます。登録済みで演習のない5コースは「演習なし」と表示し、手動完了できます。未収録の28コースは目標と「未収録」を表示し、完了にできません。
- 進捗一覧は既定でマップ順にし、低正答率順へ切り替えられるようにします。完了操作は明示的な利用者操作に限り、解説閲覧や正答率で自動完了・アクセス制限を行いません。

### 保存・互換性

- 新しい保存キー、version、上限、カテゴリIDの検証方法を第1段階で実装定義します。保存値の入力検証、破損・不正データ、容量超過、書き込み失敗のエラー処理を保ちます。backupの書き出しと復元は新形式の両領域を一体として検証します。
- 正式リリース前は旧形式を読み込まず、旧データの変換・自動削除を行いません。旧形式との後方互換性は要件に含めません。これは2026-11-12の明示的な方針であり、#43等の以前の互換条件をこの範囲で改訂します。
- 2領域に分けただけで複数キーの更新が原子的になる、または複数タブ競合がなくなるとは扱いません。部分保存・競合時の状態、再試行、復元の挙動を第1段階で定義して検証します。

## 3段階の実施順

### 1. 基盤を準備する

新しい2領域の保存形式、検証と失敗時の回復、両領域を含むbackup、十進採点の入口を整えます。旧形式のmigrationや互換アダプターは作りません。

**完了条件:** 保存形式のkey/version/上限とカテゴリID契約が定まり、正常・不正・破損・容量超過・保存失敗を検証できること。2領域の片側だけが更新された場合や複数タブから更新された場合の表示・復旧方法が決まっていること。backupの往復で両領域を復元できること。十進丸めの正負の境界と許容誤差0をテストできること。

### 2. 基本統計量を新経路へ切り替える

4節の連続解説ページと別ページの演習を `lesson-registry` 正本で実装し、必要な本文block・overview・演習slotと図の登録だけを追加します。新しい演習定義、初回判定、コース全体の直近25件を接続し、マップ・進捗・バックアップの入口をつなぎます。節内の小問を直近25件へ含めるかは、この段階の完了前に決定します。

**初回切替の範囲:** 基本統計量の4節と1ページの演習、コース全体の直近25判定、独立した手動完了、backup往復。他の収録済み5コースは演習なし・手動完了可、未収録28コースは完了不可とします。

**完了条件:** 初回判定・再回答・問題再生成・再読み込み、0件と25件上限、節リンクと誤答後の復習導線が期待どおり動き、採点・進捗・演習記録が互いを自動更新しないこと。`lesson-contract`、`lesson-view`、`resolve-screen`、backup/store、演習統合のテストを通し、正負の丸め、破損・保存失敗も確認すること。画面変更はproduction buildで320px幅・キーボード・ブラウザー経路を確認すること。

### 3. 旧機能を整理する

新経路の動作を確認した後、旧演習・feedback画面、preview分岐、不要になった履歴snapshotと関連経路を削除します。`question-*` を一括削除せず、採点と他の収録済み教材5コースからの参照を確認して対象を絞ります。必要な文書と受入記録を更新します。

**完了条件:** 基本統計量が新経路だけで利用でき、対象外の収録済み教材と共有採点部品に回帰がないこと。`npm run check` と `npm run build` が通り、公開QAが対象Issueで必要な場合はその結果も記録されていること。

各段階は依存順に進め、作業は原則としてIssueごとに分けてPRにします。段階間で新旧経路を同時に恒久運用することや、2つ目のコースを新形式で制作することは前提にしません。

## 実装時の検証と範囲外

- 実装中は `npm run check`、`npm run build` と変更した契約・画面・保存・演習統合テストを行います。今回の計画文書PRではコードテストやブラウザー検証を追加しません。
- 実装検証では正負の丸め、0件・25件上限、初回だけの記録、再生成、保存失敗、破損データ、backup往復、コース分類、ルート遷移とキーボード操作を確認します。これは新実装の機能検証であり、完了済みのモック比較受入検証をやり直すものではありません。
- 対象外は、他教材への新形式展開、2つ目のコース制作、旧データの移行、サーバー・アカウント、生成画像、汎用widget機構、数値採点の汎用分数・平方根対応です。
