## 0. 要約

SfQCは、**QC検定2級を学習目標に置き、統計学が初めての人に「解説を読んで理解し、問題を解き、間違えた理由を解消する」体験を提供する、解説主体のWeb教材と問題集**である。

中核となる学習ループは **解説 → 確認・演習 → 採点 → 誤答に対応する解説 → 再演習 → 定着確認** とする。単純な問題数の充実や試験形式の再現よりも、このループが迷わず繰り返せることを優先する。

GitHub Pagesで静的配信し、学習・演習・採点・統計計算・学習履歴の管理は原則としてブラウザ内で完結する。教材の図解はSVG、Canvas、HTML/CSSなど、**コードから再現できる描画**を第一とし、生成AIによる画像・スライド・生成アセットは使用しない。

## 1. 目的・対象と境界

### 1.1 目的

- 初学者・非理系出身者が、QC検定2級の統計関連項目へ段階的に到達できること。
- 統計の用語や数式を、意味、前提、具体例、計算手順、適用条件を結びつけて理解できること。
- 理解が不十分な箇所へ即座に戻り、学び直し後に演習へ復帰できること。
- 学習範囲、進捗、習熟の手応え、復習が必要な項目を視覚的に確認できること。

### 1.2 対象利用者

高校数学の知識に空白がある人、統計学を体系的に学んだことのない人を主対象とする。QC検定3級の既習者も想定するが、数学・統計の既習を前提としない導入ルートを設ける。

### 1.3 スコープ

QC検定2級の**統計・品質管理手法に関係する知識**を中核とする。数学の基礎、3級・4級の関連事項は、2級内容を理解するための前提単元として含める。

QC検定2級の「実践」分野すべての網羅は当初の対象外とする。将来拡張は否定しないが、**SfQCでの学習達成度を、そのままQC検定2級全体の合格可能性として扱わない**。公式の出題範囲とアプリの収録範囲の差は明示する。

### 1.4 非目標（初期段階）

本試験の過去問転載、大規模な模擬試験の完成、アカウント・クラウド同期、AIチャットによる自動解説生成、ランキング・ゲーミフィケーション、専用サーバーの構築は初期目標としない。

## 2. 教育設計の原則

### 2.1 解説を主役にする

「問題を解かせてから必要な知識を教える」だけでなく、利用者が**解説から入り、理解を確認するために問題へ進める**構造を基本とする。各単元は原則として「何を理解するか → 具体例 → 用語・数式 → コード描画の図解 → 例題 → 確認問題 → 次に学ぶ内容」で構成する。

### 2.2 初学者向けの説明と、厳密さを両立する

- ELI5を文章の明瞭さの指針とし、できるだけ平易な日本語と具体例を用いる。
- ただし、**すでに修了した前提単元は習得済みとして扱い**、毎回すべてを比喩や言い換えに戻さない。
- 数学的に必要な用語・記号・定義・仮定・適用範囲を省略しない。比喩は理解への入口であり、定義の代替にはしない。
- 公式について「何を求める式か」「各記号の意味」「使える条件」「結果の解釈」を説明し、必要な場合は導出の概要も示す。
- 数式に出てくる記号や操作が未習なら、必要な基礎単元へのリンクを置く。用語解説での循環参照は避ける。

### 2.3 前提知識に戻りやすくする

単元は固定IDと前提単元IDを持つ有向グラフとして管理する。解説内の重要な用語・式・操作から対応する復習教材に移動できるようにする。

前提への移動は一方通行にせず、**元の解説・問題・読んでいた箇所へ戻る導線**を確保する。将来、補足をその場で開くUIも検討する。リンクの多用で本文が読みにくくならないよう、主要な前提は明示し、補助的な前提は折りたたみ等で整理する。

### 2.4 誤答を学習へつなぐ

採点結果には正誤だけでなく、原則として「なぜ違うのか」「どの概念が関係するのか」「何を読むと理解し直せるのか」を示す。可能な問題では、誤答選択肢ごとに`misconception`（誤解の種類）や`remediationLessonIds`を付け、対応解説へ誘導する。

推奨ループ: **誤答 → 具体的なフィードバック → 関連解説／前提の復習 → 短い確認 → 同じ概念の別問題 → 間隔を空けた再確認**。再演習では単に直前の答えを暗記して正解した状態と、概念を理解した状態を区別できるようにする。

最初から誤答原因を完全に自動推定することは目指さない。選択肢に紐づく明示的な解説リンクを優先し、自由記述・数値入力では検出可能な典型的誤りから段階的に対応する。

### 2.5 図解はコードファースト

教材内のグラフ、分布曲線、概念図、スライド相当の図版は、**SVG / Canvas / HTML / CSS等のソースコードから描画可能で再現性のあるもの**とする。AI生成画像、画像生成モデルが作成したアセット、生成画像を貼り付けたスライドは使用しない。

静的な図も原則としてコード描画で作り、必要に応じてパラメータ操作で動的に変化させる。図の教育上の目的、変数と単位、スケール、凡例、計算条件を明示する。色覚・キーボード操作・スクリーンリーダーに配慮し、テキストによる代替説明を用意する。

## 3. 学習体験の基本フロー

1. 学習者が学習マップから対象単元を選択する（必要なら前提チェックを提示する）。
2. 平易な導入と操作可能な図を通じて、概念と数式のつながりを学ぶ。
3. 例題・確認問題・計算問題に進み、解答する。
4. 正答・誤答いずれも根拠を確認できる。誤答時には関係する単元・該当節へジャンプできる。
5. 復習後は元の問題に復帰し、必要に応じて別パラメータの問題で再確認する。
6. 単元の進捗・演習の成績・復習予定を更新する。

最低限必要な画面は、学習マップ、単元解説、演習、解答とフィードバック、進捗ダッシュボード、データ管理である。モバイルでも同じループを使えるようにする。

## 4. カリキュラムの暫定構成

以下は**教育上の学習順**を示す暫定案であり、公式レベル表の章立てそのものではない。別途、公式QC検定レベル表の各項目との対応表を作成し、範囲を追跡する。

| レイヤー | 暫定的な学習範囲 |
|---|---|
| 0 数学の橋渡し | 四則計算、分数、割合、指数、平方根、Σ、代数式の変形 |
| 1 記述統計 | 平均・中央値、散らばり、分散・標準偏差、ヒストグラム、標本 |
| 2 確率 | 事象、条件付き確率、期待値、分散、確率変数 |
| 3 確率分布 | 二項・ポアソン・正規分布、標本分布、中心極限定理の理解 |
| 4 推定・検定 | 標準誤差、信頼区間、仮説検定、平均・分散・比率の検定 |
| 5 工程の統計 | 管理図、工程能力指数、工程のばらつきの読み方 |
| 6 関係性の分析 | 相関、単回帰、残差、分散分析 |
| 7 実験計画 | 一元配置・二元配置、主効果・交互作用 |
| 8 品質管理への応用 | 抜取検査、OC曲線、信頼性に関する統計的考え方 |

着手優先度は「0 数学の橋渡し」および「1 記述統計」を高くする。内容の選定はQC検定2級から逆算し、目的に結びつかない一般統計学への際限ない拡張は避ける。

## 5. コンテンツのデータ設計（案）

UIと教材データを分離する。教材の追加時にアプリコードを大きく改変しなくてもよい設計を目指す。

### 5.1 単元・解説

各単元には、安定した`lessonId`、タイトル、学習目標、必要な前提単元ID、セクションID、教材本文、数式、図解コンポーネント参照、確認問題ID、関連する公式レベル表項目ID、参考資料、改訂版数を持たせる。

前提単元間の循環がないこと、参照した解説や節が実在することを自動検査する。複数ページに分かれても、戻り先となる節IDは維持する。

### 5.2 問題

各問題には、安定した`questionId`、対象概念・単元ID、難易度、問題形式、設問と条件、正解、解法と根拠、誤答別の説明、復習先（単元・節ID）、参考資料、改訂版数を持たせる。

数値をランダム生成する問題は、シード、入力パラメータ、計算条件、許容誤差、丸め規則、解答の検算方法を定義する。紛らわしい選択肢の重複や複数正解が生じないよう検査する。初期は選択式と数値入力を中心とし、複雑な自由記述採点は対象外とする。

### 5.3 出典・改訂管理

出典URL、資料名、版、確認日、該当範囲、利用目的を紐づける。公式の出題範囲を**参照**し、本文・設問・図解は独自に制作する。出版物や過去問を許可なく複製しない。外部のコードや素材を採用する場合もライセンスを個別に確認する。

## 6. 学習履歴と達成度

初期版では、未着手／学習中／演習中／復習待ち／定着確認済みなどの**状態**と、正答率・試行数・最終実施日・復習履歴などの**観測値**を分けて保存する。

正答率だけで理解度を断定しない。問題数が少ない場合や、同一問題を短時間で解き直した場合には、習熟の確信度が低いことを分かるようにする。習熟度や復習スケジュールの判定式・閾値は、後続Issueで仮説として定義し、評価する。**統計の学習達成度を、根拠のない「QC2級合格確率」に変換しない**。

可視化は単元別進捗、前提関係の達成状況、問題種別の成績、苦手分野と復習予定を中心にする。学習者が**次に何を復習するとよいか**を判断できる画面を優先する。

## 7. 技術方針（候補・未確定）

- **配信:** GitHub Pagesを利用し、静的ファイルを公開する。GitHub Actionsでビルド・検査・デプロイを行う。
- **フロントエンド:** React + TypeScript + Viteを第一候補とする（確定は技術選定Issue）。
- **描画:** SVGを基本とし、必要に応じてCanvas、HTML/CSS、数値操作UIを併用する。グラフライブラリへの過度な依存を避け、教育上重要な図は仕様・算出式を把握できる形にする。
- **数式・統計:** KaTeX等の表示ライブラリ、jStat等の数値計算ライブラリを候補とし、精度・対応する関数・保守状況・ライセンスを検証する。
- **ローカル保存:** IndexedDB等を候補とする。スキーマバージョン付きのJSONエクスポート／インポートと破損時の安全な取り扱いを必須要件にする。
- **オフライン:** 将来的にPWA/Service Workerで対応する。初回配信以外にサーバーを必須とする機能は置かない。
- **プライバシー:** 学習履歴を外部サーバーに送信しないことを基本とする。認証と利用者追跡は初期版に設けない。

ライブラリと技術構成は「候補」であり、実装前にライセンス、bundleサイズ、GitHub Pagesのサブパス、オフライン時の挙動を確認して決める。

## 8. 品質・受入方針

機能単位の完了条件に加えて、学習上の正確性を検証する。

- **説明品質:** 初学者が前提を辿れること、定義・条件が正しく、比喩が誤解を生まないこと。
- **解答品質:** 正解と途中計算を独立に検算すること。乱数問題はシード再現可能とし、境界値・丸め・選択肢の重複をテストすること。
- **リンク品質:** 解説→演習→誤答復習→元の設問、の往復が動作し、参照先のIDが欠落していないこと。
- **保存品質:** リロード後も記録が残ること。エクスポート→インポートの復元・スキーマ変更・不正な入力の検証を行うこと。
- **表示品質:** PCとスマートフォンで読みやすく、キーボード操作ができ、図の意味を文章でも確認できること。
- **配信品質:** GitHub Pages上で直接URLを開いた場合や更新後の再読み込みでも動作すること。

最初の縦断的な試作（vertical slice）は「平均・分散・標準偏差」とし、**解説から入り、誤答による復習を経て、戻って再演習できる**ことを必須のE2E受入条件とする。

## 9. 段階的な開発計画（暫定）

| フェーズ | 成果物と完了の目安 |
|---|---|
| P0 定義 | 公式レベル表との対応マスター、単元の前提グラフ、教材・問題スキーマの草案、主要画面の導線 |
| P1 基盤 | GitHub Pagesへの最小デプロイ、CI、画面遷移、ローカルデータ管理の足場 |
| P2 縦断MVP | 「平均・分散・標準偏差」の解説・コード描画・演習・誤答フォロー・学習記録が連携する |
| P3 統計の拡充 | 確率分布、推定・検定等を拡充し、復習・習熟表示を改善する |
| P4 QC手法の拡充 | 管理図、工程能力、実験計画、回帰、抜取検査等を順次追加する |
| P5 充実・検証 | 公式レベル表との差分監査、教材品質の第三者レビュー、公開用の導線と運用改善 |

各フェーズの具体的な受入条件は、開始前のIssueで定義する。全範囲の教材完成をMVPの受入条件にしない。

## 10. GitHub運用ルール

基本サイクルを **Issue（目的・範囲・受入条件）→ 実装ブランチ → PR（検証結果）→ レビュー → マージ／Issueクローズ → 次のIssue** とする。

1. Issueには背景、変更対象、スコープ外、成果物、受入条件、検証方法、依存Issueを記す。大きな論点は調査Issueと実装Issueを分ける。
2. 原則として1 Issueに対して1 PRを対応させる。大きすぎる場合は独立して検証できる単位へ分割する。
3. PRには関連Issue、実装内容、設計上の判断、テスト結果、残存課題、画面変更があればキャプチャ等を記す。
4. PRレビューでは**統計・教育内容の正しさ**と**実装の正しさ**を別々に確認する。レビューで生じた未解決の重大事項はマージ前に解消する。
5. PRの完了・マージを確認してからIssueを閉じる。残課題や新たな作業は次のIssueとして明記する。ステータスや評価を推測でPASSとしない。
6. 方針に変更が出た場合は、このドラフトを含む関連文書もPRで更新する。決定事項をIssueコメントだけに埋もれさせない。

この文書の初回登録後、**最初の開発IssueはP0の「QC検定2級の統計関連出題範囲と前提単元の対応表作成」**を優先する。技術スタックは前提とせず、教育要件と教材構造を先に固定する。

## 11. 保留事項と検討用Issue

- 公式レベル表の項目粒度と、独自カリキュラムの単元粒度の対応方式。
- 導入の数学単元をどこまで必修・任意復習とするか。
- 問題タイプ、数値入力の丸め規則、誤答パターンのタグ設計。
- 習熟度・間隔反復の閾値と、十分な試行数の定義。
- 初期の対象環境、保存形式、オフライン必須範囲、ライブラリの選定。
- 教材・コードの公開ライセンス、外部参照資料の更新確認方法。
